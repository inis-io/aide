# 01 - 对账账单下载（Biller）落地文档

## 1. 背景

统一支付网关的核心价值之一是统一对账。核心包已预留账单能力的全部接口位，但三个官方 Provider 均未实现：

- `pay/pay.go:81-84` — `Biller` 接口（`FetchBill(context.Context, BillRequest) (BillResult, error)`）
- `pay/pay.go:64-79` — `BillRequest` / `BillResult` 预留结构体
- `pay/capability.go:19` — `CapBill = "bill:fetch"`
- `pay/registry.go:139` — `validateProvider` 已校验 `CapBill` 声明与接口实现的一致性

本需求在**不改变现有边界**的前提下，为支付宝与微信支付落地 `FetchBill`；PayPal 本期明确不实现（见 §3.2）。

## 2. 目标与非目标

### 2.1 目标

- 支付宝、微信支付 Provider 声明并实现 `CapBill`，按日（可选按月）获取账单下载地址；
- 支持可选的「代下载」：Provider 直接返回账单原始字节，并完成大小限制与完整性校验；
- `Driver` 增加 `FetchBill` 门面方法，走与其他能力一致的校验、观测、日志链路。

### 2.2 非目标

- **不解析账单内容**：ZIP/CSV 解压、字段解析、与本地订单的 diff 对账均属业务系统职责；
- 不做账单落盘存储（业务可用 `storagex` 自行保存 `Content`）；
- 不做 PayPal 账单（见 §3.2）；
- 不做历史账单批量回补的编排（业务可用 `taskx` 周期任务驱动）。

## 3. 已核实的 SDK 事实（gopay v1.5.122）

以下接口签名与字段均已从模块源码核实，升级 gopay 版本时必须复核。

### 3.1 支付宝（`alipay/v3`）

`alipay/v3/payment_api.go:194`：

```go
func (a *ClientV3) DataBillDownloadUrlQuery(ctx context.Context, bm gopay.BodyMap) (aliRsp *DataBillDownloadUrlQueryRsp, err error)
```

- `bm` 必填 `bill_type`、`bill_date`（SDK 内 `CheckEmptyError` 强制）；
- `bill_type`：`trade`（交易账单，基于支付宝交易收单）/ `signcustomer`（资金账单，基于余额收入支出）；月账单仅 `trade` 类型支持，`bill_date` 传 `yyyy-MM`；日账单传 `yyyy-MM-dd`；
- 响应 `alipay/v3/model_payment.go:189`：`BillDownloadUrl string`、`BillFileCode string`；错误走 `ErrResponse`，与现有 `checkAlipayResponse` 复用；
- 下载地址拿到后是**普通 HTTPS GET**（zip 文件流），无需签名。

### 3.2 微信支付 V3（`wechat/v3/bill.go`）

```go
func (c *ClientV3) V3BillTradeBill(ctx context.Context, bm gopay.BodyMap) (wxRsp *BillRsp, err error)     // bill.go:19
func (c *ClientV3) V3BillFundFlowBill(ctx context.Context, bm gopay.BodyMap) (wxRsp *BillRsp, err error)  // bill.go:53
func (c *ClientV3) V3BillDownLoadBill(ctx context.Context, downloadUrl string) (fileBytes []byte, err error) // bill.go:160
```

- `V3BillTradeBill` 参数：`bill_date`（`yyyy-MM-dd`，为空 SDK 默认前一天）、`bill_type`（`ALL` / `SUCCESS` / `REFUND`）、`tar_type`（`GZIP`，缺省为数据流）；
- `V3BillFundFlowBill` 参数：`bill_date`、`account_type`（`BASIC` 基本账户 / `OPERATION` 运营账户 / `FEES` 手续费账户）、`tar_type`；
- 响应 `BillRsp.Response *TradeBill`（`model_bill.go:23`）：`HashType`（固定 `SHA1`）、`HashValue`、`DownloadUrl`；
- **微信的 download_url 必须带签名 GET**（`V3BillDownLoadBill` 已封装签名请求），不能像支付宝那样裸 URL 交给任意 HTTP 客户端下载——这是「代下载」在微信侧几乎必选的原因；
- `BillRsp` 的 `verifySyncSign` 已由 SDK 完成，错误走 `ErrResponse`，复用现有 `checkResponse`。

### 3.3 PayPal 本期不实现的理由

PayPal 无「申请-下载」式的商户对账单 API：交易明细靠 `GET /v1/reporting/transactions` 分页检索或异步报表（生成轮询），语义与 `FetchBill`（单次调用拿下载地址）不匹配。强行适配会把异步轮询状态机引入核心包。本期 PayPal **不声明 `CapBill`**，`Driver.FetchBill` 对其返回 `ErrUnsupportedCapability`，语义自然成立。

## 4. 核心包设计

### 4.1 `BillType` 枚举（`pay/capability.go` 追加）

```go
// BillType - 账单类型
type BillType string

const (
	BillTypeTrade    BillType = "trade"     // 交易账单
	BillTypeFundFlow BillType = "fund-flow" // 资金账单（账户维度资金变动）
)
```

### 4.2 `BillRequest` / `BillResult` 扩展（`pay/pay.go`）

```go
// BillRequest - 账单请求
type BillRequest struct {
	_ noUnkeyedLiterals
	// Date - 账单日期：日账单 yyyy-MM-dd；月账单 yyyy-MM（是否支持月账单由 Provider 决定）
	Date string `json:"date"`
	// Type - 账单类型，缺省 BillTypeTrade
	Type BillType `json:"type"`
	// Fetch - 是否由 Provider 代下载账单内容；false 时只返回 DownloadURL
	Fetch bool `json:"fetch"`
	// Extensions - Provider 专属扩展
	Extensions Extensions `json:"extensions"`
}

// BillResult - 账单结果
type BillResult struct {
	// DownloadURL - 账单下载地址（Fetch=false 时业务自行下载；注意微信 URL 需签名 GET，见扩展说明）
	DownloadURL string `json:"downloadUrl"`
	// FileName - 网关给出的账单文件标识（如支付宝 bill_file_code），可为空
	FileName string `json:"fileName"`
	// Content - Fetch=true 时代下载的账单原始字节（通常为 zip/gzip 包），未代下载为 nil
	Content []byte `json:"-"`
	// HashType - 网关给出的摘要算法（微信为 SHA1），无则为空
	HashType string `json:"hashType"`
	// HashValue - 网关给出的账单摘要值，无则为空
	HashValue string `json:"hashValue"`
	// Truncated - 代下载内容因大小上限被截断（此时 HashValue 校验已跳过）
	Truncated bool `json:"truncated"`
	// Raw - 按捕获策略保留的原始响应
	Raw *RawPayload `json:"-"`
}
```

### 4.3 代下载大小上限（`pay/options.go`）

`OpenOptions` 追加：

```go
// BillMaxBytes - 代下载账单的字节上限（压缩包体积），默认 32 MiB
BillMaxBytes int64
```

`normalizeOpenOptions` 默认 `32 << 20`，配套 `WithBillMaxBytes(int64) Option`。超过上限：保留已读字节、置 `Truncated=true`、跳过摘要校验，**不视为错误**（业务可选择重试或自行下载）。

### 4.4 `Driver.FetchBill`（`pay/driver.go`）

与其他能力同构：

- `capabilityOf[Biller](this, CapBill)`；
- 入参校验：`Date` 必须匹配 `^\d{4}-\d{2}(-\d{2})?$`；`Type` 为空时归一为 `BillTypeTrade`，非枚举值报 `ErrInvalidRequest`；
- `validateOwnExtensions` 命名空间校验；
- `observe(ctx, "bill:fetch", request.Date, ...)` 走统一观测链路（`OutNoHash` 用日期摘要即可）。

## 5. Provider 落地细节

### 5.1 支付宝（`pay/providers/alipay/alipay.go`）

- `sdkClient` 接口追加：`DataBillDownloadUrlQuery(context.Context, gopay.BodyMap) (*alipayv3.DataBillDownloadUrlQueryRsp, error)`；
- `Capabilities()` 追加 `pay.CapBill`；
- `FetchBill` 实现：
  - `Type` 映射：`BillTypeTrade → "trade"`、`BillTypeFundFlow → "signcustomer"`；
  - `body := gopay.BodyMap{"bill_type": mapped, "bill_date": request.Date}`；月账单（`yyyy-MM`）仅允许 `BillTypeTrade`，否则报 `ErrInvalidRequest`；
  - 响应填 `DownloadURL = rsp.BillDownloadUrl`、`FileName = rsp.BillFileCode`、`Raw = capture(...)`；
  - `Fetch=true` 时用 `options.Client` 发起普通 GET（无需签名），经 `io.LimitReader(BillMaxBytes+1)` 读取，超上限置 `Truncated`；支付宝不提供摘要，`HashType/HashValue` 留空；
- 新增扩展（可选）：`BillOptions` 预留命名空间 `alipay`，本期可为空结构体，保持扩展点形态一致。

### 5.2 微信支付（`pay/providers/wechat/wechat.go`）

- `sdkClient` 接口追加三行：`V3BillTradeBill` / `V3BillFundFlowBill` / `V3BillDownLoadBill`；
- `Capabilities()` 追加 `pay.CapBill`；
- 新增扩展 `BillOptions`：

  ```go
  // BillOptions - 微信账单专属扩展
  type BillOptions struct {
      // TradeBillType - 交易账单类型：ALL / SUCCESS / REFUND，缺省 ALL
      TradeBillType string `json:"tradeBillType,omitempty"`
      // AccountType - 资金账单账户：BASIC / OPERATION / FEES，缺省 BASIC
      AccountType string `json:"accountType,omitempty"`
  }
  ```

- `FetchBill` 实现：
  - `BillTypeTrade → V3BillTradeBill`（`bill_type` 取扩展，缺省 `ALL`）；`BillTypeFundFlow → V3BillFundFlowBill`（`account_type` 取扩展，缺省 `BASIC`）；统一 `tar_type = GZIP`；**不支持月账单**，`yyyy-MM` 格式报 `ErrInvalidRequest`；
  - 响应填 `DownloadURL`、`HashType`、`HashValue`、`Raw`；
  - `Fetch=true` 时调 `V3BillDownLoadBill` 代下载（SDK 内部完成签名 GET）；字节数超 `BillMaxBytes` 置 `Truncated`；未截断且 `HashType == "SHA1"` 时对 `Content` 做 SHA-1 比对 `HashValue`，不一致返回 `ErrGatewayRejected`（`Outcome=OutcomeUnknown`，视为下载损坏）；
  - `Fetch=false` 时**文档必须提示**：微信 `DownloadURL` 需商户签名 GET 才能下载，业务无法裸 URL 拉取，微信侧建议总是 `Fetch=true`。

### 5.3 PayPal（`pay/providers/paypal/paypal.go`）

- 不改代码；`Capabilities()` 维持不声明 `CapBill`。

## 6. 安全与边界

- 账单 `Content` 含全量交易明细，属敏感数据：**默认不进入 Raw 捕获**（`Raw` 只保留「申请账单」的 JSON 响应，不含文件内容）；`Content` 不落日志、不进 Observer；
- 代下载复用 `options.Client`（含超时与重定向剥头策略）；支付宝下载地址为 `alipay.com` 域，无需额外白名单（地址来自验签后的网关响应）；
- 摘要校验只在微信侧且未截断时执行；校验失败按网关错误处理，不产生部分可信数据；
- 账单日期不做「必须早于今天」的强制校验（各网关容忍度不同），交给网关报错。

## 7. 测试要求（沿用假 SDK，禁止联网）

- 核心包：`BillRequest` 日期格式校验、`Type` 归一与非法值、`Driver.FetchBill` 能力位缺失返回 `ErrUnsupportedCapability`、观测链路调用次数；
- 支付宝：假 `sdkClient` 断言 `bill_type`/`bill_date` 映射、月账单仅限 trade 的拒绝、`Fetch=false` 不发起下载、`Fetch` 超上限置 `Truncated`；
- 微信：三类 `TradeBillType`/`AccountType` 缺省与显式值、月账单拒绝、`V3BillDownLoadBill` 字节与 SHA-1 校验（构造正确/错误 `HashValue` 各一例）、截断时跳过校验；
- 注册表一致性：`Capabilities` 声明 `CapBill` 但未实现接口（反之亦然）时 `Registry.New` 报错（现有 `validateProvider` 已覆盖，补用例即可）。

## 8. 任务拆解

1. `pay`：`BillType` 枚举 + `BillRequest`/`BillResult` 扩展 + `OpenOptions.BillMaxBytes` + `Driver.FetchBill` + 核心测试；
2. `alipay`：接口追加 + `FetchBill` + 代下载 + 测试；
3. `wechat`：`BillOptions` 扩展 + `FetchBill` + 代下载与摘要校验 + 测试；
4. 文档：`pay/README.md` 能力矩阵加「账单」列（Alipay/WeChat 标 ✓，PayPal 标 —），安全约定补一条「账单内容不进日志与 Raw」。

## 9. 验收标准

- `go build ./... && go vet ./... && go test ./...` 全绿（含 `pay` 与两个 Provider 包新增用例）；
- 支付宝、微信均可用一次调用拿到 `DownloadURL`，微信可在 `Fetch=true` 下拿到经 SHA-1 校验的完整字节；
- PayPal `FetchBill` 返回 `ErrUnsupportedCapability`；
- 任意路径下账单内容不出现在日志、Observer 与 `Raw` 中。
